# 学生管理系统使用说明

本系统通过浏览器管理学生、课程和选课，数据保存在本机 MySQL 中。

## 启动与停止

用 VS Code 打开 Student-Web 文件夹，在终端输入：

```powershell
.\start.ps1
```

输入本机 MySQL root 密码后，浏览器会自动打开。保持启动终端打开；按 Ctrl+C 停止服务。

| 项目 | 内容 |
|---|---|
| 网页地址 | http://127.0.0.1:5178 |
| 网页账号 | demo_admin |
| 网页密码 | Demo12345! |
| Java 后端地址 | http://127.0.0.1:8088 |
| MySQL 数据库 | student_web_demo_20261010 |

网页账号与 MySQL 账号是两套账号。网页登录使用 demo_admin；启动终端输入 MySQL root 密码。MySQL 密码不写入代码或配置文件。

修改代码后，先停止服务，再执行启动脚本重新构建。网页当前使用构建版本，编辑源码不会立即更新页面。

## 导入班级学生和课程

先启动系统，再在另一个项目终端输入：

```powershell
.\import-school.ps1
```

脚本读取指定的 2026 春季班级课表与 2025 级综测表，匹配班级后导入学生和课程。重复执行会跳过已有记录，已有数据不被覆盖。

本次导入包含 18 个班级、864 名学生和 27 门课程。2025 级软件工程 4 班有 44 名学生。首页人数还包括之前保留的练习记录。

| 系统字段 | 导入方式 |
|---|---|
| 姓名 | 使用名单中的姓名 |
| 学号 | 单独保存名单中的学号，作为唯一身份字段；不是数据库自增 ID |
| 邮箱 | 按学号@lingnan生成，用作本机系统的邮箱字段，可由管理员改为真实邮箱 |
| 班级／院系 | 使用名单中的完整班级名称 |
| 课程名称 | 从班级课表中提取并去重 |
| 课程编号 | 自动生成本机管理编号，不是学校官方课程代码 |
| 学分、出生日期 | 源资料未提供，留空 |
| 个人选课、课程成绩 | 未提供个人明细，需手动登记 |

综测分数与排名不作为课程成绩导入。课表中的上课周次、地点和教师目前没有对应管理界面。

导入前的记录保存在 .runtime/school-import-before.json；导入报告和本次新增的记录编号保存在 .runtime/school-import-report.json。需要撤销学生导入时，可以依据报告中的编号执行软删除，再通过回收站恢复。

## 功能与操作

| 菜单 | 功能 |
|---|---|
| Dashboard | 查看真实学生数、课程数和宽幅班级人数分布图 |
| Students | 添加、查询、编辑学生，删除记录，上传照片和导出 CSV |
| Courses | 按专业、班级逐层查看课程，也可查看全部课程、添加课程 |
| Enrollments | 登记选课、独立录入成绩、查看退课历史 |
| 账号管理 | 管理员创建教师、管理员账号，查看账号角色 |
| Recycle bin | 查看和恢复被删除的学生 |
| Export | 导出学生数据 |

添加学生：进入 Students，点击 Add student，填写 Name（姓名）、Email（邮箱）、Department（班级／院系），点击 Create。刷新后记录仍保留。

修改学生：点击学生行的编辑按钮，修改字段后保存。
删除学生：点击删除按钮，确认后进入回收站；需要恢复时进入 Recycle bin。

课程浏览：先点击专业卡片，再点击班级卡片，即可看到该班课表中的课程。点击顶部路径可返回上一级；每层使用“上一页”“下一页”翻页。点击“全部课程”查看完整目录，新增课程也在完整目录中显示。

专业、班级、学生与班级课程关系保存在数据库中。分类页面人数依据当前有效学生，新增、删除、恢复和调班后自动重新查询。管理员可以在 Courses 的“管理班级课表”中新增班级或调整课程，也可以通过“安排教师／班级”为课程指定教师。

课表中的课程安排不等于个人选课记录。重新导入时优先按独立学号匹配学生，修改邮箱后也不会重复创建档案；已有姓名或班级调整保留并记入报告。导入补全源课表课程关系，保留手动新增的课程安排与已有专业归属，不覆盖已有课程信息，不会自动生成个人选课。

课程没有学分时显示“未提供”。首页已删除平均年龄、空选课趋势和模拟增长率，没有为它们添加替代模块。班级标签使用加深的原色背景和黑字。

学生搜索支持姓名、邮箱和学号；单独按班级筛选也生效。导出只包含有效学生，使用 UTF-8；照片通过带登录凭据的请求读取，只允许管理员、本人和对应任课教师访问。

## 账号与角色

公开注册只创建学生账号，账号和新档案在同一事务中保存。已有名单中的学生不要重复注册：管理员在 Students 对应行点击“绑定账号”，为其创建新学生账号，或填写已有学生账号的用户名进行绑定。一个账号最多对应一份学生档案。学生登录和刷新页面时由后端确认本人身份，浏览器不能自行选择其他人的档案。

教师和管理员账号由管理员在“账号管理”中开通。公开注册不能选择这些角色。本机 demo_admin 由 localdemo 配置在后端启动时初始化，启动脚本不再调用公开注册接口创建管理员。

| 角色 | 可执行的操作 |
|---|---|
| 管理员 | 管理学生、回收站和导出；绑定账号；维护专业班级课表；安排教师；管理选课和成绩 |
| 教师 | 查看本人任教课程及其有效选课学生；维护本人课程的选课和成绩；查看对应学生照片 |
| 学生 | 查看本人档案、照片、选课和成绩；更新本人照片；退选尚未评分的本人课程 |

教师初次授课前，管理员先安排教师并登记学生选课。教师的名单和首页统计按本人任教课程查询，不能访问其他教师的学生或成绩。

## 选课、成绩与删除规则

登记选课时不填写成绩，初始状态为“待评分”；成绩在 Enrollments 单独录入，使用 A+、A、A-、B+、B、B-、C+、C、C-、D、F 等级。学生端展示实际保存的成绩。相同学生与课程不能重复登记，数据库唯一约束和事务锁共同保护并发提交。

退课保留历史记录，重新选课使用原记录；已录成绩的记录不能退课。当前课程目录按现有资料管理，尚未拆分多个学期的开课与重修。

删除学生后，档案进入回收站，停止登录和普通业务操作，不计入有效学生、有效选课统计和默认导出。选课与成绩历史保留，恢复后重新参与有效统计。学生首页不再生成模拟学习进度或虚构截止日期；统计查询失败时显示错误，不伪装成零人数。

## 首次升级与回滚

本次会新增专业、班级与课程关联表，以及学生的学号、班级、账号关联和选课退选字段，不删除现有学生与成绩。通过 start.ps1 启动时，脚本从本机 MySQL 服务配置定位 mysql.exe 和 mysqldump.exe，在后端更新表结构之前备份已有练习库，并检查重复选课。备份失败或存在重复选课时停止启动，不自动删除记录。备份保存在被 Git 忽略的运行目录中，文件名以 database-before-upgrade 开头。

已有分类仅在首次启动时由分类种子补入数据库；后续启动保留管理页面的手动修改。原来使用 12 位学号@lingnan 的记录会提取独立学号，已有手动学号保持原值；旧学生账号不会按姓名自动认领档案，须经管理员绑定。

升级前代码的回滚点是提交 407a330。如果新版已经写入真实库，回滚必须配套恢复升级前的数据库备份，避免旧版把退课历史当成有效选课。备份文件包含本机数据，不要上传公开仓库。

## 验证

后端目录下使用 Maven 执行：

```powershell
mvn -Dspring.profiles.active=h2 test
```

现有 30 个测试覆盖账号关联、注册事务回滚、学生和教师越权、重复与并发选课、退课与成绩历史、软删除与恢复、动态班级人数、图片权限以及输入校验。测试使用 H2 隔离数据库，不连接本机真实学生库。

前端目录下执行 npm run lint，以及 npm run build -- --mode demo，检查代码和网页构建。真实 MySQL 的升级、备份和迁移还需要在提供本机数据库密码后通过启动脚本验证。

## 程序与数据库的关系

浏览器发送请求给 Java 后端，Java 后端连接本机 127.0.0.1:3306 的 MySQL 并保存数据。DataGrip 可以连接同一个 MySQL 查看数据。

系统仅供本机访问，不需要开启上网代理。原始名单和课表保持不变。

## 获取代码后的环境准备

仓库包含项目源码和专业班级课程分类目录，不包含本机 MySQL 数据、学生名册、运行日志、依赖缓存和编译结果。

本机启动脚本使用已经准备好的 JDK、Node.js、MySQL 和 .tools 中的 Maven。其他电脑获取代码后，需要先准备 Java 17 以上版本、Node.js、MySQL 和 Maven，并安装前端依赖，再配置自己的数据库连接。直接下载代码不会同时下载本机环境或数据。

使用 MySQL 配置时，通过 DEMO_DB_PASSWORD 提供数据库密码，通过 DEMO_JWT_SECRET 提供至少 32 字节的登录签名密钥。start.ps1 会在本机运行时临时提供它们。H2 配置供开发测试使用。
